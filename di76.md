# di76 - the math behind the compression

di76 is based on the Stillwell 1175 JSFX by Thomas Scott Stillwell (BSD license, see the header in `jsfx/di76.jsfx`). This document explains how the DSP works, what the working variables do, and notes the variables that silently default to zero because they have no UI and are never assigned.

di76 and di75 share the same simplified compressor; `jsfx/di75.jsfx` additionally keeps the "All" ratio mode with its program-dependent ratio follower, while di76 adds a high-pass filter in front.

## Changes from the original 1175

- Removed the deprecated "Blown Capacitor" ratio modes, the "All" ratio mode, and the wet/dry Mix slider. The Ratio slider offers only 4, 8, 12 and 20, so the `capsc` detector scaling, the `allin` logic and the parallel dry path are all gone. The plugin is 100% wet: output is always `input * grv * makeupv`.
- Simplified the DSP like di75: dead code and no-op variables removed (`maxover`/`runmax` peak tracker, the `rmscoef`/`runave` RMS scaffolding, placeholder attack/release temps, redundant explicit zeroing), and `grv`, `rpos` and the attack/release coefficient math inlined. Verified bit-identical to the unsimplified code in simulation.
- Added a high-pass filter straight from my dipass plugin as the first slider and the first stage of the audio path. 0 = off. Same one-pole 6 dB/octave filter as dipass, quirks included (see section 1). Verified bit-identical to running dipass in front of the compressor.

All variables in a JSFX are global and are zero-initialized before `@init` runs. Anything never assigned a value stays `0` — this matters later.

## The signal chain at a glance

For every sample pair, the plugin does:

```
samples → high-pass filter → level detector → dB over threshold
       → attack/release smoothing → ratio law (dB of gain reduction)
       → linear gain → apply makeup
```

It is a feed-forward compressor: the gain applied to the audio is computed from a detector that watches the (filtered) incoming signal.

## 1. The high-pass filter (`@sample`, first stage)

```
hpon ? (
  hp0 = (spl0 - old_spl0) * hpa0 + hp0 * hpb1;
  hp1 = (spl1 - old_spl1) * hpa0 + hp1 * hpb1;
  old_spl0 = spl0;
  old_spl1 = spl1;
  spl0 = hp0;
  spl1 = hp1;
);
```

- This is exactly my dipass filter: one-pole high-pass with `hpb1 = exp(-4*$pi * cutoff / srate)` and `hpa0 = (hpb1 + 1) * 0.5`, state in `hp0/hp1` (previous outputs) and `old_spl0/old_spl1` (previous inputs). First-order → **6 dB per octave** (measured, see the dipass notes in the README).
- Quirk included: the `-4` exponent in `hpb1` puts the -3dB corner one octave above the slider value (slider 100 Hz → corner ~200 Hz). I kept dipass's exact behavior so the two plugins match.
- `slider1 = 0` bypasses the filter entirely (`hpon`), avoiding the marginal `b1 = 1` case.
- Because it is the first thing in `@sample`, the filter feeds **both** the audio and the detector: lows are removed from the signal *and* from what the compressor reacts to (p-floor rumble no longer triggers gain reduction).

## 2. The level detector (`@sample`)

```
det = max(abs(spl0), abs(spl1));
```

- `det` is the detector level as a plain linear amplitude (1.0 = full scale).
- The original 1175 ran this through a power-domain one-pole smoother with a coefficient (`rmscoef`) of `0` — no memory — so it reduced to exactly this: an **instantaneous peak detector**. The scaffolding was removed; the behavior (and the sound) is unchanged.

## 3. dB over threshold (`@sample`)

```
overdb = max(0, log2db * log(det/cthreshv));
```

- `log()` in JSFX is the natural log. `log2db = 20/ln(10) = 8.68589...`, so `log2db * log(x)` is exactly `20 * log10(x)` — plain decibels.
- `cthreshv = exp(cthresh * db2log)` is the threshold as a linear amplitude (`db2log = ln(10)/20` is the inverse constant).
- `det/cthreshv` is how many times hotter than threshold the signal is; `log` of that, scaled, is how many dB over. `max(0, ...)` clamps it: below threshold, `overdb = 0`.

## 4. Attack/release smoothing - the envelope follower (`@sample`)

```
overdb > rundb ? (
  rundb = overdb + atcoef * (rundb - overdb);    // attack
) : (
  rundb = overdb + relcoef * (rundb - overdb);   // release
);
overdb = rundb;
```

`rundb` is a smoothed copy of `overdb`, updated by the classic one-pole exponential smoother:

```
y[n] = x[n] + a * (y[n-1] - x[n])      with  a = exp(-1 / (tau * srate))
```

`tau` is a time constant: after `tau` seconds the output has closed about 63% of the gap toward the input (about 95% after 3*tau). Smaller `a` means faster tracking.

- **Which coefficient is used is decided per sample**: if the raw detector wants *more* gain reduction than the smoothed value (signal getting louder), the **attack** coefficient is used; otherwise the **release** coefficient. `atcoef` comes from the Attack slider (20-2000 uS) and `relcoef` from the Release slider (20-1000 mS), each computed inline as `exp(-1/((slider * unit) * srate))`. This asymmetry is what makes it an envelope follower: it snaps down on loud material and eases back at the release rate when the program gets quiet (when `overdb = 0`, `rundb` decays toward 0 at the release rate, restoring unity gain).
- After the update, `overdb = rundb`, so downstream math uses the *smoothed* value.

### The ratio follower (`averatio`, `runratio`) — di75 only

di76 dropped this along with "All" mode; it is documented here because it still exists in di75.

- If the raw `overdb` jumps more than 5 dB above the smoothed `rundb` (a sudden transient), `averatio` is snapped to `4`.
- `runratio` chases `averatio` with its own one-pole pair: very fast while attacking (`ratatcoef`, 10 uS time constant) and very slow while releasing (`ratrelcoef`, 0.5 s time constant).
- Then `averatio = runratio` every sample, and in "All" mode the effective ratio is `cratio = 12 + averatio`. This is the "program-dependent" part: a big transient pushes the All-mode ratio toward 16:1.
- Quirk: because `averatio` is set equal to `runratio` at the end of every sample, the release branch has zero gap to close, so `runratio` does not actually decay back. In practice `averatio` **latches** at the value from the last big transient (or 0 before the first one, so "All" starts as `12:1`).

## 5. The static ratio law (`@sample`)

```
grv = exp(-overdb * (cratio-1)/cratio * db2log);
```

This is the standard feed-forward compressor curve. If the smoothed detector sits `R` dB over threshold and the ratio is `p`, the output should sit `R/p` dB over threshold, so the gain that achieves that is:

```
g_dB = R/p - R = -R * (1 - 1/p) = -R * (p - 1) / p
```

which is exactly the exponent here with `R = overdb` and `p = cratio` (`cratio` is always `ratio` in di76). Below threshold `overdb = 0`, so the exponent is 0 and `grv = 1` (unity gain). The `exp(... * db2log)` is the dB-to-linear conversion: `grv = 10^(gr/20)`.

## 6. Applying the gain (`@sample`)

```
spl0 *= grv * makeupv;
spl1 *= grv * makeupv;
```

`makeupv = exp((makeup + autogain) * db2log)` is the output Gain slider as a linear multiplier (`autogain = 0`, see Observations). The plugin is fully wet — there is no dry path.

## 7. The gain reduction meter (`@sample` and `@gfx`)

- `gr_meter` tracks the gain reduction: it snaps instantly to `grv` when gain drops (new minimum), and decays toward 1 (0 dB of reduction) otherwise. `gr_meter_decay = exp(1/(1*srate))` is slightly greater than 1 per sample — roughly a 1 second time constant — and `@gfx` multiplies by `exp(1/30)` per frame (~30 fps) so the meter keeps relaxing even when audio stops. It is initialized to 1 in `@init` (JSFX would otherwise zero it, and the meter would read "-inf dB" until the first gain drop).
- `@gfx` draws it as a bar on a log (dB) scale with tick marks every 3.01 dB (factors of `sqrt(2)` in linear gain), plus a numeric readout.

## Working variables - quick reference

| Variable | Set in | Role |
|---|---|---|
| `log2db`, `db2log` | `@init` | dB <-> linear conversion constants (20/ln10, ln10/20) |
| `hpcutoff`, `hpon` | `@slider` | High-pass cutoff (Hz); `hpon` bypasses the filter when slider1 = 0 |
| `hpb1`, `hpa0` | `@slider` | One-pole high-pass coefficients (same math as dipass) |
| `hp0`, `hp1`, `old_spl0`, `old_spl1` | `@sample` | High-pass filter state |
| `thresh`, `cthresh` | `@slider` | Threshold in dB; `cthresh` is the knee-adjusted value actually used |
| `threshv`, `cthreshv` | `@slider` | Same two, as linear amplitude |
| `ratio`, `cratio` | `@slider` | Selected and effective ratio (identical in di76; `cratio = 12 + averatio` only in di75's "All" mode) |
| `makeup`, `makeupv` | `@slider` | Output gain (dB and linear) |
| `atcoef`, `relcoef` | `@slider` | One-pole smoother coefficients for attack/release |
| `det` | `@sample` | Detector level, linear amplitude |
| `overdb` | `@sample` | dB over threshold; raw for one line, then overwritten with smoothed `rundb` |
| `rundb` | `@sample` | Smoothed dB over threshold (state) — the value the ratio law uses |
| `grv` | `@sample` | Gain reduction as a linear multiplier |
| `gr_meter`, `gr_meter_decay` | `@init`, `@sample` | GR meter value and its decay toward 1 |

## Observations: variables that default to zero (no UI, never assigned)

JSFX zeroes every variable before `@init`, so anything listed here is not just unused — it is `0`, and that `0` actively shapes the sound:

1. **`softknee`** — chooses `cthresh`. At `0`, `cthresh = thresh`: a **hard knee**, the full ratio engages the instant the detector crosses the threshold. Non-zero would lower the comparison threshold by 3 dB (`cthresh = thresh - 3`), widening the onset region into a soft knee. No UI exists to turn it on.

2. **`autogain`** — added to the makeup gain in dB: `makeupv = exp((makeup + autogain) * db2log)`. At `0` there is **no automatic make-up gain**; only the manual Gain slider contributes. This looks like a hook for an auto-makeup feature that was never exposed.

Secondary notes:

- `threshv` is computed but never used; only `cthreshv` feeds the detector.
