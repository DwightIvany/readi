# di76 - the math behind the compression

di76 is based on the Stillwell 1175 JSFX by Thomas Scott Stillwell (BSD license, see the header in `jsfx/di76.jsfx`). This document explains how the DSP works, what the working variables do, and notes the variables that silently default to zero because they have no UI and are never assigned.

If you want this same math with the no-ops collapsed into a minimal, sound-equivalent implementation, see `jsfx/di75.jsfx`.

## Changes from the original 1175

- Removed the deprecated "Blown Capacitor" ratio modes. The Ratio slider now offers only 4, 8, 12, 20 and All, so the `capsc` detector scaling is gone and `overdb` uses `log2db` directly.
- Removed the wet/dry Mix slider. The plugin is 100% wet: output is always `input * grv * makeupv`.

All variables in a JSFX are global and are zero-initialized before `@init` runs. Anything never assigned a value stays `0` — this matters later.

## The signal chain at a glance

For every sample pair, the plugin does:

```
samples → level detector → dB over threshold → attack/release smoothing
       → ratio law (dB of gain reduction) → linear gain → apply makeup
```

It is a feed-forward compressor: the gain applied to the audio is computed from a detector that watches the incoming signal.

## 1. The level detector (`@sample`)

```
aspl0  = abs(spl0);
aspl1  = abs(spl1);
maxspl = max(aspl0, aspl1);   // louder channel steers the detector (linked stereo)
maxspl = maxspl * maxspl;     // amplitude → instantaneous power
runave = maxspl + rmscoef * (runave - maxspl);   // one-pole smoothing on power
det    = sqrt(max(0, runave));                   // back to amplitude
```

- `det` is the detector level as a plain linear amplitude (1.0 = full scale).
- The squaring/square-root pair exists so the smoothing filter `runave` can work in the **power** domain, which is where RMS averaging belongs.
- With `rmscoef = 0` (see Observations), the smoother has no memory: `runave = maxspl`, so `det = max(|spl0|, |spl1|)` — an **instantaneous peak detector**, not RMS.

## 2. dB over threshold (`@sample`)

```
overdb = max(0, log2db * log(det/cthreshv));
```

- `log()` in JSFX is the natural log. `log2db = 20/ln(10) = 8.68589...`, so `log2db * log(x)` is exactly `20 * log10(x)` — plain decibels.
- `cthreshv = exp(cthresh * db2log)` is the threshold as a linear amplitude (`db2log = ln(10)/20` is the inverse constant).
- `det/cthreshv` is how many times hotter than threshold the signal is; `log` of that, scaled, is how many dB over. `max(0, ...)` clamps it: below threshold, `overdb = 0`.

## 3. Attack/release smoothing - the envelope follower (`@sample`)

```
overdb - rundb > 5 ? (averatio = 4;);

overdb > rundb ? (
  rundb   = overdb + atcoef * (rundb - overdb);    // attack
  runratio = averatio + ratatcoef * (runratio - averatio);
) : (
  rundb   = overdb + relcoef * (rundb - overdb);   // release
  runratio = averatio + ratrelcoef * (runratio - averatio);
);
overdb   = rundb;
averatio = runratio;
```

`rundb` is a smoothed copy of `overdb`, updated by the classic one-pole exponential smoother:

```
y[n] = x[n] + a * (y[n-1] - x[n])      with  a = exp(-1 / (tau * srate))
```

`tau` is a time constant: after `tau` seconds the output has closed about 63% of the gap toward the input (about 95% after 3*tau). Smaller `a` means faster tracking.

- **Which coefficient is used is decided per sample**: if the raw detector wants *more* gain reduction than the smoothed value (signal getting louder), the **attack** coefficient is used; otherwise the **release** coefficient. `atcoef = exp(-1/(attime * srate))` with `attime` = Attack slider in seconds (20-2000 uS); `relcoef` likewise with Release slider (20-1000 mS). This asymmetry is what makes it an envelope follower: it snaps down on loud material and eases back at the release rate when the program gets quiet (when `overdb = 0`, `rundb` decays toward 0 at the release rate, restoring unity gain).
- After the update, `overdb = rundb`, so downstream math uses the *smoothed* value.

### The ratio follower (`averatio`, `runratio`)

- If the raw `overdb` jumps more than 5 dB above the smoothed `rundb` (a sudden transient), `averatio` is snapped to `4`.
- `runratio` chases `averatio` with its own one-pole pair: very fast while attacking (`ratatcoef`, 10 uS time constant) and very slow while releasing (`ratrelcoef`, 0.5 s time constant).
- Then `averatio = runratio` every sample, and in "All" mode the effective ratio is `cratio = 12 + averatio`. This is the "program-dependent" part: a big transient pushes the All-mode ratio toward 16:1.
- As written, the chase has a quirk: because `averatio` is set equal to `runratio` at the end of every sample, the release branch has zero gap to close, so `runratio` does not actually decay back. In practice `averatio` **latches** at the value from the last big transient (or 0 before the first one). In the fixed-ratio modes (4/8/12/20) `averatio` is never used at all — `cratio = ratio` directly.

## 4. The static ratio law (`@sample`)

```
gr  = -overdb * (cratio - 1) / cratio;
grv = exp(gr * db2log);
```

This is the standard feed-forward compressor curve. If the smoothed detector sits `R` dB over threshold and the ratio is `p`, the output should sit `R/p` dB over threshold, so the gain that achieves that is:

```
g_dB = R/p - R = -R * (1 - 1/p) = -R * (p - 1) / p
```

which is exactly `gr` with `R = overdb` and `p = cratio`. Below threshold `overdb = 0`, so `gr = 0` and `grv = 1` (unity gain). `grv = exp(gr * db2log)` is the same dB-to-linear conversion as the threshold: `grv = 10^(gr/20)`.

## 5. Applying the gain (`@sample`)

```
spl0 *= grv * makeupv;
spl1 *= grv * makeupv;
```

`makeupv = exp((makeup + autogain) * db2log)` is the output Gain slider as a linear multiplier (`autogain = 0`, see Observations). The plugin is fully wet — there is no dry path.

## 6. The gain reduction meter (`@sample` and `@gfx`)

- `gr_meter` tracks the gain reduction: it snaps instantly to `grv` when gain drops (new minimum), and decays toward 1 (0 dB of reduction) otherwise. `gr_meter_decay = exp(1/(1*srate))` is slightly greater than 1 per sample — roughly a 1 second time constant — and `@gfx` multiplies by `exp(1/30)` per frame (~30 fps) so the meter keeps relaxing even when audio stops.
- `@gfx` draws it as a bar on a log (dB) scale with tick marks every 3.01 dB (factors of `sqrt(2)` in linear gain), plus a numeric readout.

## Working variables - quick reference

| Variable | Set in | Role |
|---|---|---|
| `log2db`, `db2log` | `@init` | dB <-> linear conversion constants (20/ln10, ln10/20) |
| `thresh`, `cthresh` | `@slider` | Threshold in dB; `cthresh` is the knee-adjusted value actually used |
| `threshv`, `cthreshv` | `@slider` | Same two, as linear amplitude |
| `ratio`, `cratio` | `@slider`, `@sample` | Selected ratio; `cratio` is the effective one (varies in "All" mode) |
| `allin` | `@slider` | 1 when ratio = "All" |
| `makeup`, `makeupv` | `@slider` | Output gain (dB and linear) |
| `attime`, `reltime` | `@slider` | Attack (s) / release (s) time constants |
| `atcoef`, `relcoef` | `@slider` | One-pole smoother coefficients for attack/release |
| `ratatcoef`, `ratrelcoef` | `@init` | One-pole coefficients for the ratio follower (10 uS / 0.5 s) |
| `runave` | `@sample` | Smoothed detector power (state) |
| `det` | `@sample` | Detector level, linear amplitude |
| `overdb` | `@sample` | dB over threshold; raw for one line, then overwritten with smoothed `rundb` |
| `rundb` | `@sample` | Smoothed dB over threshold (state) — the value the ratio law uses |
| `averatio`, `runratio` | `@sample` | Transient-snapped / smoothed ratio follower (state); only used in "All" mode |
| `gr`, `grv` | `@sample` | Gain reduction in dB, then linear |
| `runmax`, `maxover` | `@sample` | Vestigial peak tracker — dead code, see below |
| `gr_meter`, `gr_meter_decay` | `@init`, `@sample` | GR meter value and its decay toward 1 |

## Observations: variables that default to zero (no UI, never assigned)

JSFX zeroes every variable before `@init`, so anything listed here is not just unused — it is `0`, and that `0` actively shapes the sound:

1. **`rmscoef`** — the one-pole smoothing coefficient for the detector power `runave`. At `0` the filter has no memory, so the detector is an **instantaneous peak detector**: `det = max(|spl0|, |spl1|)`. If it were set (the natural spot would be `@init`, e.g. `rmscoef = exp(-1/(0.005 * srate))` for ~5 ms), `det` would become a true RMS-ish average and the compressor would respond to loudness rather than momentary peaks. As shipped, the Attack slider alone tames peaks.

2. **`softknee`** — chooses `cthresh`. At `0`, `cthresh = thresh`: a **hard knee**, the full ratio engages the instant the detector crosses the threshold. Non-zero would lower the comparison threshold by 3 dB (`cthresh = thresh - 3`), widening the onset region into a soft knee. No UI exists to turn it on.

3. **`autogain`** — added to the makeup gain in dB: `makeupv = exp((makeup + autogain) * db2log)`. At `0` there is **no automatic make-up gain**; only the manual Gain slider contributes. This looks like a hook for an auto-makeup feature that was never exposed.

4. **`maxover` (with `runmax`)** — vestigial program-dependent release machinery. `runmax` is a release-smoother fed by `maxover`, and `maxover` is fed back `runmax` — but nothing ever pushes `maxover` above its initial `0`, so both sit at `0` forever. The comment says "highest peak for setting att/rel decays in reltime": the intent was clearly for `maxover` to track the recent peak over-threshold (something like `maxover = max(maxover, overdb)`) so attack/release times could adapt to program material. As written it is **dead code**, and the release time is governed solely by the Release slider. The only functional program-dependence left is the `averatio` snap in "All" mode (section 3).

Secondary notes:

- `threshv` is computed but never used; only `cthreshv` feeds the detector.
- `averatio`/`runratio` start at `0`, so "All" mode starts as `12:1` (before any >5 dB transient snaps it toward `16:1`, where it latches — see section 3).
